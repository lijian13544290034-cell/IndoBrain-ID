# V2.0B Basic Vocabulary Library QA

The vocabulary page is intentionally independent at `/vocabulary`. It uses the existing `IndonesianSpeechButton` inside `IndonesianAudioProvider`, so it retains the current Azure TTS provider, request deduplication, cache, loading, and failure behaviour.

Favorites reuse the existing profile store with stable `VOC-…` keys. This keeps vocabulary resources distinct from Experience IDs without changing current Experience favorite behaviour. The vocabulary page reads the same persisted profile after refresh. No viewing, playback, copy, search, or favorite action grants Indonesia Power.

Search is client-side for this first version and matches Indonesian text, Chinese meaning, normalized key, tags, and concise usage notes. The audit script validates all IDs, language pairs, normalization uniqueness, category counts, Harvest intersection, and representative Chinese/Indonesian/tag/no-result searches.

## Verification result

- 300 published entries: 30 each across Time, Numbers, Colors, Directions, People & Titles, Common Verbs, Office, Kitchen, Transport, and Airport.
- 102 entries match an existing normalized Experience Harvest item; the remaining 198 are reviewed foundational supplements.
- No missing required fields and no duplicate normalized keys.
- Local UI verification: all-category count (300), airport filter (30), Chinese search, Indonesian search, empty state, and persisted `VOC-` favorite toggling passed.
- Local audio controls correctly use the shared provider; this local environment has no Azure credentials, so they safely show the existing configured-state message rather than attempting browser TTS.

No migration is added. The existing account/membership gap documented in V2.0A remains unchanged; `requiredMembershipTier` is metadata only and no membership gate is enabled.
