# 移动端交互规范（375 / 390 / 430）— Quick Speak & AI Coach

> **版本**：1.0.0  
> **适用基线**：IndoBrain-ID `a86dde0`（RC2-B2-3）  
> **目标页面**：`/learn-chinese/ai-coach`（Quick Speak 落地页）及其上层的 `/learn-chinese/*` 学习区  
> **性质**：设计规范。本轮不修改仓库代码。文中"现状"均为只读核实结果，标注了文件与行号。

---

## 0. 为什么是 375 / 390 / 430 这三个宽度

这三个宽度不是随便挑的，它们分别对应中国大陆与印尼市场实际在用的三类设备：

| 宽度 | 代表机型 | 逻辑像素 | 关键约束 | 设计含义 |
|---|---|---|---|---|
| **375** | iPhone SE(2/3)、iPhone 8、部分 Android 小屏 | 375 × 667 | **最窄**，且**屏幕最矮**（667） | 这是**下限**。任何在 375 上不成立的布局，都不成立。 |
| **390** | iPhone 12/13/14、Pixel 6/7 | 390 × 844 | **基准**，刘海 + home indicator | 主设计稿按此宽度出图。 |
| **430** | iPhone 15 Pro Max / 16 Pro Max | 430 × 932 | **最宽**，仍然单列 | 不能因为宽了就变成两栏——拇指横跨距离变大，反而更难用。 |

**硬规则**：三个宽度下**都用单列布局**，只在 430 上允许**增大留白与字号**，**不允许**切两栏。理由：Quick Speak 的核心动作是"单手竖持 + 拇指点麦克风"，两栏会把主 CTA 挤到侧边。

## 2. 布局栅格与间距

### 2.1 水平栅格

| 宽度 | 页面左右 padding | 内容最大宽度 | 单列卡内 padding | 卡片间距 |
|---|---|---|---|---|
| 375 | 16px（`px-4`） | 343 | 20px | 12px |
| 390 | 16px（`px-4`） | 358 | 24px | 12px |
| 430 | 20px（`px-5`） | 390 | 24px | 16px |

**现有代码核验**：`MandarinAiCoachExperience.tsx:187` 用 `px-4` + `max-w-xl`（36rem = 576px）。所以在 375/390/430 上 `max-w-xl` **从不生效**（都被 100% 宽 + px-4 限制），实际内容宽度分别是 343 / 358 / 398。

> **规范建议**：保留 `max-w-xl`（作为 Pad / 横屏的上限），但**在 ≤430 时不追加额外约束**。430 时建议把 `px-4` 提升到 `px-5`，让内容宽度从 398 降到 390，留出更明显的手指缓冲区。

### 2.2 垂直间距刻度（8pt 制，但只用 5 个值）

| Token | 值 | 用在哪 |
|---|---|---|
| `S1` | 4px | 拼音与汉字之间、圆点之间 |
| `S2` | 8px | 按钮图标与文字、进度点与标签 |
| `S3` | 12px | 卡片内元素组之间 |
| `S4` | 20px | 卡片内 padding（375）/ 卡片之间 |
| `S5` | 32px | 大区块之间（如目标句区与 CTA 区） |

**禁止**使用 6 / 10 / 14 / 18 / 22px 这类非刻度值。现有代码里 `mt-3`(12) / `mt-5`(20) / `mt-6`(24) 混用，24px 不在刻度上——规范建议把 `mt-6` 统一降到 `mt-5`(20)。**24px 只允许出现在 430 宽的空隙放大场景。**

### 2.3 垂直可用高度（关键）

| 宽度档 | 视口高 | 顶部安全区 | 底部导航 + 安全区 | **内容可用高** |
|---|---|---|---|---|
| 375×667（SE） | 667 | 20（状态栏，非刘海） | 71 + 0 | **576** |
| 390×844（iPhone 14） | 844 | 47（刘海） | 71 + 34 | **692** |
| 430×932（15 Pro Max） | 932 | 59（灵动岛） | 71 + 34 | **768** |

> **375×667 的 576px 是全规范最紧的预算**。Quick Speak 首屏必须装进 576px（含顶栏）。前一份文档《Quick Speak》§5.1 的高度预算给的是 446~526px，**加上顶栏 48 + 阶段进度 20 = 68，合计 514~594**——**在 375×667 上正好贴着上限，超了 18px**。这是必须处理的：见 §3.3 的折叠规则。

**规范**：

| 宽度 | 形态 |

| 375 | **6 个圆点**，直径 6px，间距 6px，当前点 8px + 主色，已完成点主色 60%，未完成 `--ib-border-soft` |

| 430 | 同上 + 圆点下方 10px 阶段名（`Pilih` / `Dengar` / `Ucap` / `Perbaiki` / `Ubah` / `Selesai`） |

**可访问性**：圆点组必须带 `role="progressbar"` + `aria-valuenow={stageIndex+1}` + `aria-valuemax={6}` + `aria-label`，且**不能**只靠颜色区分（当前点用尺寸差异，不只用色）。

| 规则 | 说明 |
|---|---|
| 主 CTA 与导航的最小间距 | 20px |

### 3.7 键盘弹出（文字输入）

Quick Speak 允许打字替代录音。键盘弹出时（Android 常见 240~300px、iOS 291~336px）：

| 要求 | 说明 |
|---|---|
| 输入框必须滚入可视区 | 用 `scrollIntoView({ block: 'center' })`，不用 `block: 'start'`（会被顶栏挡） |

### 4.2 字体族与语言分流

**现状**：`<html lang="zh-CN">`（`app/layout.tsx:33`），中文与印尼语混排在同一页。AI Coach 已用 `lang="zh-CN"` + `lang="id"` 属性分流（如 `MandarinAiCoachExperience.tsx:41` 的 `lang="zh-CN"` span）。

| 规则 | 说明 |
|---|---|
| 中文文本必须带 `lang="zh-CN"` | 影响系统字体回退与屏幕朗读发音 |
| 印尼语文本必须带 `lang="id"` | 否则 TalkBack / VoiceOver 会用中文音读印尼语 |
| **不要**给整页设 `font-family` 只写中文字体 | 印尼语会掉到难看的回退字体 |
| 数字与拉丁字符 | 用系统默认无衬线，不另外指定 |

**这是可访问性硬要求**：印尼用户用 TalkBack（Android）比例高于中国用户，`lang` 缺失会让朗读完全不可懂。

## 5. 触控与手势

### 5.1 触控目标尺寸

| 元素 | 最小尺寸 | 现状 |
|---|---|---|
| 主 CTA（麦克风） | 48 × 48（全宽时高 48） | ✅ `min-h-12` |
| 次按钮（听 / 慢） | 48 × 48 | ✅ `min-h-12` |
| 底部导航项 | 56 × 56 | ✅ `min-h-14` |
| 返回按钮 | 44 × 44 | ⚠️ 现状是文字链接，高度不足 44 |
| 打字入口 | 44 × 44 | 需新增 |
| 圆点进度 | 不可点 | — |
| 拆块（chunks） | 44 × 44（可点时） | 需新增 |

**规范**：任何可点元素，其**点击区**（不是视觉尺寸）必须 ≥ 44×44。做法是用 `::before` 扩展到 44×44 而不改变视觉大小。

### 5.2 手势

| 手势 | 允许 | 说明 |
|---|---|---|
| 竖向滚动 | ✅ | 唯一主要手势 |
| 横向滑动 | ❌ 禁止 | 不引入 swipe 切阶段，会与浏览器"返回"手势冲突 |
| 长按 | ❌ 禁止 | 不做长按播放 / 长按删除 |
| 双击 | ❌ 禁止 | 会与缩放冲突 |
| 下拉刷新 | ❌ 禁止 | Quick Speak 进行中下拉刷新会丢会话 |

**`overscroll-behavior`**：Quick Speak 的滚动容器建议加 `overscroll-behavior-y: contain`，防止 iOS 的橡皮筋效果让主 CTA 从底部被拉出可视区。

### 5.3 震动与触觉反馈

**不新增** `navigator.vibrate()`。理由：
1. iOS Safari 不支持 `vibrate()`；
2. 印尼中低端 Android 上震动体验差异大；
3. 会让人误以为"对了"或"错了"，干扰教学判定。

3. **375 宽**：顶栏右侧只显示阶段序号，时间预算单独一行小字。

**除此之外，三个宽度下的布局结构、信息层级、元素顺序必须完全一致。**

## 8. 性能与视觉的边界（不增加复杂动画）

**用户明确要求：不为视觉效果增加复杂动画或昂贵语音服务。** 本规范的对应条款：

| 允许 | 禁止 |
|---|---|
| CSS `transition` 的 `background-color` / `opacity` / `transform`（≤ 200ms） | JS 驱动的逐帧动画（`requestAnimationFrame` 循环） |
| 进度条宽度过渡（现状已用 `transition-all`） | 页面切换的整页转场动画 |
| 骨架屏（纯 CSS 渐变） | Lottie / Rive / 视频背景 |
| 静态 emoji 作为图标 | 动图 emoji、SVG 精灵动画 |
| 系统原生滚动惯性 | 自定义滚动（`scroll-behavior: smooth` 仅在跳锚点时用） |

**新增资产预算**：Quick Speak 的视觉资产**只允许新增 0 个图片**。所有图标用 emoji（🎙️ / 🔊 / 🐢 / 💬）或纯 CSS 绘制，与现状一致。

## 9. 浏览器测试断言清单（三宽度）

以下每条都可以在浏览器层直接断言（对应《真实用户测试计划》§浏览器测试层）：

| # | 断言 | 375 | 390 | 430 |
|---|---|---|---|---|
| M-01 | `document.documentElement.scrollWidth <= innerWidth`（无横向溢出） | 必过 | 必过 | 必过 |
| M-02 | 主 CTA 的 `getBoundingClientRect().bottom <= innerHeight`（首屏可见） | 必过 | 必过 | 必过 |
| M-03 | 主 CTA 的 `offsetHeight >= 48` | 必过 | 必过 | 必过 |
| M-04 | 所有 `button` 点击区 ≥ 44×44 | 必过 | 必过 | 必过 |
| M-05 | 底部导航与主 CTA 间距 ≥ 20px | 必过 | 必过 | 必过 |
| M-06 | 顶栏不被状态栏遮挡（`rect.top >= 0` 且 `>= safe-area-inset-top`） | 必过 | 必过 | 必过 |
| M-07 | 目标句卡片单行不截断（`scrollWidth <= clientWidth`） | 必过 | 必过 | 必过 |
| M-08 | 反馈块不超过 3 行可视高度 | 必过 | 必过 | 必过 |
| M-09 | 根字号放大到 32px 后，`scrollWidth` 仍 `<= innerWidth` | 必过 | 必过 | 必过 |
| M-10 | 键盘态（模拟 300px 视口缩减）下输入框可见 | 必过 | 必过 | 必过 |
| M-11 | 所有印尼语文本节点带 `lang="id"` | 必过 | 必过 | 必过 |
| M-12 | `--ib-text-muted` 未用于承载信息的正文 | 必过 | 必过 | 必过 |

**视口设置（Puppeteer 写法）**：

```js
// 375 / 390 / 430
await page.setViewport({ width: 375, height: 667, deviceScaleFactor: 2, isMobile: true, hasTouch: true });
await page.setViewport({ width: 390, height: 844, deviceScaleFactor: 3, isMobile: true, hasTouch: true });
await page.setViewport({ width: 430, height: 932, deviceScaleFactor: 3, isMobile: true, hasTouch: true });
```

> `deviceScaleFactor` 用 2 / 3 / 3 是因为 SE 是 2x，iPhone 14 与 15 Pro Max 是 3x。`isMobile: true` 会让 `env(safe-area-inset-*)` 在 Chrome DevTools 协议下返回设备值，**否则安全区恒为 0**，M-06 会假通过。
