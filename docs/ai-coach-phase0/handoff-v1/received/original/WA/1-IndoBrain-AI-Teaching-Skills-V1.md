# IndoBrain AI Teaching Skills V1

**面向**：零基础 / 初级成年人（中国学习者学印尼语 · 印尼学习者学中文），核心诉求是**尽快能开口**。

**版本**：V1 · 2026-10-19
**性质**：内部研究与设计规范，未进入 IndoBrain 仓库，未提交 Git。

---

## 0. 总则

### 0.1 本文件解决什么问题

语言 App 的常见失败不是「没有内容」，而是**教练行为退化**：
- 用户答错 → 直接给正确答案 → 用户点「跟读」→ 系统记「已掌握」→ 明天全忘。
- 用户停顿 → 教练抢答 → 用户从此不再尝试组织语言。
- 每节课塞 8 个新词 → 用户记不住 → 判定「我没语言天赋」。

本文件把优秀人类教师在**真实课堂里反复展示、且能被研究追溯**的教学行为，拆成 AI 可执行的原子动作，并给每条动作配上「什么时候触发 / 不许做什么 / 怎样算成功 / 怎样自动验收」。

### 0.2 证据分级约定（全文统一使用）

| 标记 | 含义 | 进入产品的条件 |
|---|---|---|
| `[强证据]` | 有系统综述 / 元分析 / 多项 RCT 支持，且结果方向一致 | 可直接进入产品规则 |
| `[有限证据]` | 有实证研究，但样本小、单一语境、非同行评审，或效应方向在不同研究中不一致 | 可进入产品规则，但必须留可关闭的开关 + 埋点监控 |
| `[假设]` | 无直接实证支持，是基于相邻领域证据 + 教学经验的产品设计推断 | **不得写入对用户的承诺文案**；上线需 A/B 验证 |

详细出处见 `2-教学证据与参考文献表.md`。

### 0.3 八条产品原则（硬约束，优先级高于任何单个 Skill）

| # | 原则 | 对应的 Skill 约束 |
|---|---|---|
| P1 | 面向急需快速开口的中印尼用户，先解决"能用"，不追求"系统完整" | 所有 Skill 的输出都必须能在当次对话内被用户用出去 |
| P2 | 零基础从最短、自然、实用的词句开始 | S02 起手单位上限；S04 难度台阶 |
| P3 | 每次只增加一个信息点 | S03 / S04 的"单变量"硬规则 |
| P4 | 教练少解释、多让用户开口 | S03 的讲解字数控；S02 的输出占比 |
| P5 | 不会时逐步提示，不要立即给完整答案 | S03 提示梯度；S08 回流路径 |
| P6 | 跟读不等于掌握，必须独立表达 + 变化追问 | S07 的判定口径；S02 的 don't-count 清单 |
| P7 | 中文与印尼语分别设计教学表达，不能机械直译 | 全部 Skill 的示例；S05 的反馈语 |
| P8 | 不把 STT 识别结果等同于发音测评 | S05 / S11 的取证边界 |

> **P6 的理论根据**：Swain (1985) 输出假说的核心机制是「学习者注意到自己想说与能说之间的差距」。跟读时不存在"想说什么"的意图，因此不存在可被注意的差距，跟读在机制上无法产生输出假说所指的习得效应。这不是"跟读没用"，而是**跟读不能作为掌握的证据**。`[强证据]`（机制层面）；"跟读练习量→迁移到自由表达"的因果效应 `[有限证据]`。

> **P8 的工程含义**：STT 返回的是「系统认为你说了什么」。它可能因为口音、环境噪声、麦克风质量而错误，也可能在发音明显错误时仍返回正确文本（语言模型纠错）。因此 STT 结果只能用于**判断用户是否在说目标语、是否说出了目标词**，不能用于发音打分。真正的发音评估需要音素级对齐（如强制对齐 + GOP 打分），V1 明确不做。

### 1.2 冲突仲裁

当多个 Skill 同时想说话时，按以下优先级执行（数字小者优先）：

1. **S10 Confidence Building**（情绪优先于教学内容）
2. **S08 Error Recovery**（防止放弃）
3. **S05 Corrective Feedback**（有节流约束）
4. **S03 Scaffolding**（用户卡住时必须给）
5. **S02 / S04 / S07 / S09**（常规教学流）
6. **S06 / S11 / S12**（结构性动作）

> 反例：用户刚说完"我太笨了"，S05 仍弹"这里应该是 ng，不是 n"——违反仲裁顺序，属于硬性缺陷。

### S02 · Micro Speaking（微口语输出）

#### 1. 教学目标
让用户在**单轮 30 秒内**产出一句真实可用的目标语，且该产出**不是跟读**。核心不是"说得多"，而是"这一句他现在就能对真人说"。

#### 2. 理论依据及证据强度
- **输出假说**（Swain 1985/1995）：产出迫使学习者注意到"想说的"与"能说的"之间的差距（noticing the gap），并检验假设。`[强证据]`（机制），对"输出优于纯输入"的整体效应 `[有限证据]`（Erlam 2003 的 structured-input vs output-based 对照实验支持输出组增益更大，但 N=70、单一语法点）。
- **技能习得理论**（DeKeyser 2007）：从陈述性知识到程序化再到自动化，必须经过**有意义的重复使用**。`[强证据]`（理论框架层面），具体到"每轮一句"的最优颗粒度 `[假设]`。
- **交互假说**（Long 1996）：意义协商是习得的关键场所。`[强证据]`。

#### 3. 触发条件
每一轮教练对话的**核心输出动作**。无例外。

#### 4. 输入
```yaml
learner: { L1, target_lang, level: A0|A1, known_expressions[], session_history }
target: { expression_id, surface, pinyin_or_ipa, gloss_l1 }
context: { scene, interlocutor, user_goal }   # 例：雅加达便利店买水
constraints: { max_new_info_points: 1 }
```

#### 5. AI 教学动作
1. **给场景，不给规则**：一句话说清"你现在在哪、对面是谁、你要干什么"，不超过 20 个字（中文）/ 25 kata（印尼语）。
2. **给可用的那一句**，同时给 L1 释义 + 目标语原句 + 一次示范音频。
3. **要用户说**。不要求复述，要求"用这句话完成任务"。
4. **等待**：至少 4 秒静默，不插话。
5. **拿到输出后转 S05/S07**，不在本轮做长解释。

#### 6. 结构化输出建议
```json
{
  "skill": "S02",
  "turn_type": "micro_speaking",
  "scene": {"zh": "便利店，店员问你买什么", "id": "Toko, kamu mau beli apa?"},
  "target_expression": {"id": "exp_air_botol", "surface": "Minta air botol satu", "gloss_zh": "要一瓶水"},
  "new_info_points": 1,
  "instruction": {"zh": "对店员说：要一瓶水。", "id": "Bilang ke penjaga: minta air botol satu."},
  "expected_user_act": "produce_target_expression",
  "max_wait_ms": 12000,
  "silence_hint_ms": 4000,
  "fallback_skill": "S03"
}
```

#### 7. 成功与失败判定
| 判定 | 条件 |
|---|---|
| 成功 | 用户独立产出目标表达（允许 1 处非阻断性偏差），且**未在本次轮次内先听过完整答案** |
| 部分成功 | 用户在 S03 支架下产出（降级计入"支架下成功"，不计入"独立成功"） |
| 失败 | 用户未产出 / 产出完全无关内容 / 用户要求直接给答案 |
| **不计入成功** | 跟读、复述、朗读原文、S03 最后一档直接给全句后用户重复 |

#### 8. 禁止行为
- ❌ 一轮给两句以上新表达（违反 P3）
- ❌ 先讲语法再让用户说
- ❌ 用户还没开口就自己示范三遍
- ❌ 把 STT 识别成功写成"发音正确"
- ❌ 用户跟读后记 `mastered=true`

#### 9. 中文教学示例（印尼人学中文）
> 场景：在雅加达的奶茶店，店员问你要什么。
> 教练：「店员问你喝什么。说：**我要一杯奶茶。**」
> （给出：我要一杯奶茶 / wǒ yào yì bēi nǎi chá / Saya mau satu gelas milk tea）
> 用户说 → 判定 → 进入下一轮。

**为什么这样设计**：不先教「杯」是量词，不先教「要」的用法。整句作为**语块**先进入可用状态，量词在 S07 的变式追问里再被注意到。

#### 10. 印尼语教学示例（中国人学印尼语）
> 场景：在雅加达便利店，店员问 mau beli apa。
> 教练：「店员问你要买什么。说：**Minta air botol satu.**」
> （给出：Minta air botol satu / 要一瓶水）

**为什么不是「Saya mau beli air botol」**：后者语法正确但冗长，印尼人口语里 `minta ... satu` 更短更自然。**P7 要求分别设计，正是为了避免把中文语序直译成印尼语。**

#### 11. 边界与失败案例
1. **用户是"沉默型"**：4 秒不开口。→ 不重复催促，直接转 S03 第一档提示（给首词）。
2. **用户用 L1 回答**：说明目标表达超出当前可及范围。→ 不批评，判定为「未就绪」，S04 降一档，本轮改为"听 + 二选一"。
3. **用户说得很快但错**：不要因为"流畅"就判成功。→ 流畅不等于准确，S05 处理。
4. **用户主动说"直接告诉我吧"**：可以给，但必须标记 `scaffold_level=full_answer`，且**当轮不计入掌握**，下一轮必须重新尝试（S07）。
5. **场景不真实**：给"和国王讨论天气"这类用户一辈子用不上的场景 → 违反 P1，属于内容缺陷而非 Skill 缺陷。

#### 12. 自动化验收条件
- `AC-S02-1`：任何 `micro_speaking` 轮次的 `new_info_points` 必须恒等于 1；>1 即 fail。
- `AC-S02-2`：`instruction` 中不得出现语法术语（中文：`量词|助词|谓语|宾语|时态`；印尼语：`imbuhan|prefiks|sufiks|klausa`）。
- `AC-S02-3`：若用户输出前已收到 `surface` 的完整音频朗读 ≥2 次，该轮 `mastery_eligible=false`。
- `AC-S02-4`：`mastered=true` 的记录必须同时满足 `produced_without_full_answer=true` 且 `had_variation_check=true`（与 S07 联动）。
- `AC-S02-5`：STT 置信度低于阈值时，不得输出"发音正确/错误"类文案；只允许"我没听清，再说一次"。

### S03 · Scaffolding（支架）

#### 1. 教学目标
用户卡住时，用**最小必要帮助**把他推到"自己说出来"，而不是替他说话。支架的价值在于**被撤除**；无法撤除的支架是失败的支架。

#### 2. 理论依据及证据强度
- **Wood, Bruner & Ross (1976)** 六功能：recruitment（引发兴趣）、reduction in degrees of freedom（缩小自由度）、direction maintenance（维持方向）、marking critical features（标记关键特征）、frustration control（挫折控制）、demonstration（示范）。`[有限证据]`——**注意**：该研究是 30 名 3–5 岁儿童、单一成人导师的描述性研究，无对照组、非语言学习、非成人。它是**支架概念的源头**，不是"支架有效"的效果证据。
- **最近发展区**（Vygotsky）：在帮助下可达成的区间。`[强证据]`（理论），具体提示梯度设计 `[假设]`。
- **引导式发现**（British Council 术语库）：教师给例子，学习者自己找规律；效率低于直接讲解，因此**只用于值得花时间的项目**。`[有限证据]`（教学法共识，非效果量）。
- **EEF 元认知报告**：明确警告"通用学习技巧难以迁移"，支架必须绑定具体任务内容。`[强证据]`（指南级）。

#### 3. 触发条件（满足任一）
- 用户超过 `silence_hint_ms`（默认 4000ms）无输出
- 用户输出明显不完整（缺少目标句的核心成分）
- 用户明确表达不会（"我不会""怎么说""apa ya"）
- 用户用 L1 代替目标语
- S05 纠错后用户连续 2 次仍无法重试

#### 4. 输入
```yaml
stuck_signal: silence | incomplete | explicit_help | l1_substitution | failed_retry
failed_attempts: int
target_expression: { surface, tokens[] }
current_scaffold_level: 0..4
learner_profile: { needs_romanization: bool, prefers_audio: bool }
```

#### 5. AI 教学动作 —— **五档提示梯度（只能逐档上升，不可跳档）**

| 档 | 动作 | 示例（中文学印尼语） | 何时用 |
|---|---|---|---|
| L0 | 什么都不做，只等 | （静默） | 默认起点 |
| L1 | **给首词 + 意图提示** | 「开头是 *Minta*…… 后面是你要的东西。」 | 第一次卡住 |
| L2 | **给结构骨架（挖空）** | 「Minta ___ botol ___」 | 第二次卡住 |
| L3 | **二选一** | 「是 *Minta air botol satu* 还是 *Minta satu air botol*？」 | 第三次卡住 |
| L4 | **完整给答案** | 「跟我读完整的：Minta air botol satu。」 | 第四次，或用户明确要求 |

**关键规则**
- 每档发出后必须**再次等待 4 秒**，不得连续升级。
- L4 之后**不得**在同一轮再次要求用户"独立说"——改为下一轮（S07）。
- 用户一旦独立成功，立即**回撤两档**（下次同类场景从 L0 起）。
- 讲解字数：中文 ≤25 字，印尼语 ≤15 kata。**超过即违规**（P4）。

#### 6. 结构化输出建议
```json
{
  "skill": "S03",
  "scaffold_level": 2,
  "rationale": "second_stuck_on_same_target",
  "prompt": {"zh": "试着说：Minta ___ botol ___", "id": "Coba: Minta ___ botol ___"},
  "wait_ms": 4000,
  "escalation_allowed": true,
  "mastery_eligible": false
}
```

#### 7. 成功与失败判定
| 判定 | 条件 |
|---|---|
| 支架成功 | 用户在 L1–L3 后独立补全（该轮记 `scaffolded_success`） |
| 支架失败 | 升级到 L4 仍需用户跟读 → 记 `needs_reteach`，交 S08 |
| 支架过强 | 用户在 L1 就能完成，但系统已升到 L2 → 记 `over_scaffold` 事件，需调低默认档位 |

#### 8. 禁止行为
- ❌ 跳档（用户第一次卡住就给完整答案）
- ❌ 连续两条消息都在提示（把用户逼成听众）
- ❌ 在提示里夹带新语法知识
- ❌ 用"再想想"这种无信息量的催促
- ❌ 把 `scaffolded_success` 记为 `mastered`
- ❌ 支架后不撤除（下次同场景仍从 L2 起）

#### 9. 中文教学示例（印尼人学中文）
> 目标：**这个多少钱？**
> L1：「开头两个字是 *这个*……」
> L2：「这个 ___ 钱？」
> L3：「是 *这个多少钱* 还是 *多少钱这个*？」
> L4：「整句是：这个多少钱。」

#### 10. 印尼语教学示例（中国人学印尼语）
> 目标：**Bisa kurang?**（能便宜点吗）
> L1：「开头是 *Bisa*……」
> L2：「Bisa ___ ?」
> L3：「是 *Bisa kurang* 还是 *Kurang bisa*？」
> L4：「整句是：Bisa kurang。」

**P7 说明**：中文"能便宜点吗"直译成 `Bisa lebih murah?` 语法没错但**不地道**；印尼市场实际高频是 `Bisa kurang?`。这就是"不能机械直译"的具体含义。

#### 11. 边界与失败案例
1. **用户每次都等到 L4**：说明目标表达严重超纲（P2 违规）。→ S04 降档，不是继续加支架。
2. **用户在 L2 时突然自己说对了**：正常，立刻正面确认并回撤档位，不要因为"没用完梯度"而遗憾。
3. **提示给了但用户理解错方向**：说明提示本身有歧义。→ 记 `scaffold_ambiguous`，该条提示进人工审核队列。
4. **用户是听觉型，看罗马字反而乱**：`needs_romanization=false` 时必须给音频而非拼写。
5. **群体课场景（1 对多）**：支架会变成"一个人被帮、其他人旁观"。→ V1 明确只做 1 对 1，不支持多用户共享支架。

#### 12. 自动化验收条件
- `AC-S03-1`：`scaffold_level` 单轮升幅必须 ≤1；跳档即 fail。
- `AC-S03-2`：任一轮内出现 ≥3 次 `S03` 输出即 fail（违反"不把用户逼成听众"）。
- `AC-S03-3`：`prompt` 字符数：中文 ≤25、印尼语 ≤15 kata；超限 fail。
- `AC-S03-4`：`scaffold_level=4` 的轮次必须 `mastery_eligible=false`。
- `AC-S03-5`：上一轮 `scaffold_level=L` 且成功时，下一同类目标起始档必须为 `max(0, L-2)`。

### S04 · Adaptive Difficulty（自适应难度）

#### 1. 教学目标
把难度稳定维持在"跳一跳够得着"的区间：太简单则无聊且不产生习得，太难则挫败且不产生输出。**难度调节的颗粒度是"一次一个信息点"，不是"整课升降级"。**

#### 2. 理论依据及证据强度
- **技能习得理论**（DeKeyser 2007）：练习必须建立在**已掌握的前提**上，否则练习无效甚至有害。`[强证据]`（理论）。
- **i+1 / 可理解输入**（Krashen）：略高于当前水平。`[有限证据]`——Krashen 的输入假说整体受到较多批评（尤其"输出不必要"部分），此处只借用"难度需略高于当前"这一弱版本。
- **EFE / EEF 元认知报告 Rec.4**：设置**恰当水平的挑战**以发展自我调节。`[强证据]`（指南级）。
- **最近发展区**：`[强证据]`（理论）。
- **"每次一个信息点"的具体阈值**：`[假设]`，需 A/B 验证。

#### 3. 触发条件
每完成一个任务单元后（默认 3–5 轮 micro_speaking）。

#### 4. 输入
```yaml
unit_performance:
  independent_success_rate: 0..1
  scaffolded_success_rate: 0..1
  avg_scaffold_level_used: 0..4
  error_types: [omission, substitution, word_order, tone/pitch, register]
  time_to_first_token_ms: int
  abandonment: bool
current_difficulty: { sentence_length, token_count, novelty_ratio, scaffold_default }
```

#### 5. AI 教学动作 —— 四档调节，每次只动一个维度

| 维度 | 说明 | 上限 |
|---|---|---|
| `token_count` | 目标句的词数 | A0 起手 2–3；A1 起手 3–4 |
| `novelty_ratio` | 新词占比（未见过 / 总词数） | ≤ 1 个新信息点 / 轮（P3） |
| `sentence_length` | 是否引入从句 | A0/A1 阶段禁止 |
| `scaffold_default` | 默认起手提示档 | L0–L1 |

**升级规则**（上调一档）：`independent_success_rate ≥ 0.8` 且 `avg_scaffold_level_used ≤ 1`，连续 2 个单元。
**降级规则**（下调一档）：`independent_success_rate < 0.4` 或 `avg_scaffold_level_used ≥ 3`，任一单元即触发。
**维持规则**：其余情况不动。**"不动"是最常见的正确决策**——频繁调节本身就是干扰。

**禁止**：一次同时上调 `token_count` 和 `novelty_ratio`（违反 P3 的"单变量"原则）。

#### 6. 结构化输出建议
```json
{
  "skill": "S04",
  "decision": "hold | up | down",
  "changed_dimension": null,
  "next_unit": {"token_count": 3, "novelty_ratio": 0.33, "scaffold_default": "L1"},
  "evidence": {"independent_success_rate": 0.67, "avg_scaffold_level_used": 1.5},
  "user_visible_message": null
}
```
> `user_visible_message` 默认 `null`——**难度调节对用户静默发生**，不弹"已为你降低难度"（会打击信心，与 S10 冲突）。

#### 7. 成功与失败判定
| 判定 | 条件 |
|---|---|
| 难度合适 | 连续 2 单元 `independent_success_rate ∈ [0.6, 0.85]` 且 `avg_scaffold_level_used ≤ 2` |
| 过难 | `avg_scaffold_level_used ≥ 3` 或 `abandonment=true` |
| 过易 | `independent_success_rate = 1.0` 且 `time_to_first_token < 800ms`（明显不需要思考） |

#### 8. 禁止行为
- ❌ 一次调节多个维度
- ❌ 向用户宣告难度变化
- ❌ 因为一次失败就降级（需看整体率，除非触发 S08）
- ❌ 把"课时进度"当作难度依据（进度 ≠ 能力）
- ❌ 在 A0 阶段引入从句、被动、敬语体系

#### 9. 中文教学示例（印尼人学中文）
当前：`我要一杯奶茶`（6 词，1 新词）。连续 2 单元独立成功、很少用支架 →
升级：保留句长，仅新增 1 个新信息点，如 `我要一杯奶茶，不要糖`（仍 1 个新信息点：否定义）。
**不是**直接跳到 `我想要一杯不加糖的冰奶茶`（同时变句长 + 新词 + 定语从句 = 三个变量）。

#### 10. 印尼语教学示例（中国人学印尼语）
当前：`Minta air botol satu`（4 词）。稳定成功后 →
升级：`Minta air botol satu, yang dingin`（新增 1 个信息点：要冰的）。
**不是** `Minta air botol satu yang dingin tanpa gula ya mas`（同时 4 个新点）。

#### 11. 边界与失败案例
1. **用户心情好但能力未到**：连续蒙对 → 升级后立刻崩。→ 用 `novelty_ratio` 控制，升级只动一个维度，可回退。
2. **用户跨场景能力差异大**：点餐流利、问路全崩。→ 难度必须**按场景分别维护**，不能用一个全局等级。
3. **成人学习者"面子"因素**：降级对成年人来说比儿童更伤自尊。→ 降级必须静默（见 `user_visible_message=null`）。
4. **A0 用户被给了 A2 内容**：属内容分层错误，S04 无法补救。→ 需 S01 在入口拦住。

#### 12. 自动化验收条件
- `AC-S04-1`：单次调节 `changed_dimensions.length ≤ 1`。
- `AC-S04-2`：`novelty_ratio` 导致的新词数 ≤1 / 轮。
- `AC-S04-3`：`user_visible_message` 必须为 `null`（除非用户主动问"是不是变难了"）。
- `AC-S04-4`：A0/A1 档位的 `sentence_length` 不得包含从句标记（中：`因为|虽然|如果|的时候`；印尼：`karena|walaupun|kalau|yang` 引导的定语从句）。
- `AC-S04-5`：`abandonment=true` 必须在 1 个单元内触发 `down`。

### S05 · Corrective Feedback（纠错反馈）

#### 1. 教学目标
在**不打断表达意愿**的前提下，让用户注意到错误并立即再试一次。纠错的目标是"改一次"，不是"讲明白为什么"。

#### 2. 理论依据及证据强度
- **Li, S. (2010) 元分析**（Language Learning 60(2), 309–365；33 项原始研究）：纠错反馈整体有**中等效应且随时间保持**；隐性反馈的保持优于显性；实验室效应大于课堂；短处理效应大于长处理。`[强证据]`
- **Lyster & Saito (2010)**（15 项课堂研究）：**prompts（提示/诱导）比 recasts（重述）更有益**，尤其对初学者。`[有限证据]`（课堂研究，样本量有限但方向一致）
- **Ammar & Spada (2006)、Li (2009)**：**低水平学习者 prompt 优于 recast**；高水平者两者相当。`[有限证据]`
- **Hattie & Timperley (2007)**：反馈分 task / process / self-regulation / self 四层；**self 层（表扬人）效果最弱甚至为负**；有效反馈回答三个问题：去哪、现在怎样、下一步。`[强证据]`（综合 12 项元分析 / 196 研究；但为二级综合，效应量 0.79 应视为量级示意）
- **Kluger & DeNisi (1996)**：131 项研究中约 2/5 反馈使表现变差，多发生在反馈指向自我而非任务时。`[强证据]`
- **Finkelstein & Fishbach (2012)**：新手更接受正向反馈，专家更接受负向反馈。`[有限证据]`（消费者行为研究，迁移到语言学习 `[假设]`）
- **Kingston & Nash (2011)**：形成性评估效应量约 0.20，远低于 Black & Wiliam 的 0.4–0.7，差异源于实施保真度。`[有限证据]`——**说明"做了形成性评估"不等于"做对了"**。

#### 3. 触发条件（必须同时满足）
- 检测到错误，且
- 该错误类型**在本次会话内未被纠正过**（同一错误最多纠 2 次/会话），且
- 该错误**阻碍理解**或**属于目标句的核心成分**（非核心小错先放过），且
- 用户当前不在情绪低谷（否则 S10 优先）

**放过原则（很重要）**：A0/A1 阶段，一句 5 个词里错 3 个音，**只纠 1 个**。纠错不是查错清单。

#### 4. 输入
```yaml
user_output: { transcript, stt_confidence }
target: { surface, tokens[] }
error_analysis: [{ type, span, expected, observed, severity: blocking|minor }]
learner_level: A0|A1|A2
session_error_count: { [error_type]: int }
affect_state: neutral | frustrated | confident
```

#### 5. AI 教学动作 —— 纠错类型选择

**默认策略（A0/A1）**：`prompt > recast > explicit`。理由见 Lyster & Saito (2010) 与 Ammar & Spada (2006)。

| 类型 | 做法 | 适用 |
|---|---|---|
| **Prompt（诱导）** | 只指出位置，让用户自己改：「最后那个词，再说一次？」 | 默认首选 |
| **Recast（重述）** | 正确重述用户的话，不改话题 | 用户已尝试 1 次 prompt 仍错 |
| **Explicit（明示）** | 直接指出并给正确形式 | 错误反复出现 / 用户明确问"对不对" |
| **Metalinguistic（元语言）** | 讲规则 | **A0/A1 默认禁用**；A2 且用户主动问时才用 |

**句式模板（必须遵守）**
1. 先**确认意图**（"你要说的是要一瓶水，对吧"）——保护面子，同时验证 STT 是否听错。
2. 再**指出一处**（"最后那个 *satu* 的位置"）。
3. **再让用户说一次**。
4. 用户改对 → 立即正反馈 + 继续，**不追加解释**。

#### 6. 结构化输出建议
```json
{
  "skill": "S05",
  "cf_type": "prompt",
  "intent_confirmed": "你要一瓶水",
  "focus_span": {"expected": "air botol satu", "observed": "satu air botol"},
  "message": {"zh": "意思对了。最后三个词换个顺序，再说一次？"},
  "retry_required": true,
  "max_retry": 1,
  "pronunciation_claim": null
}
```

#### 7. 成功与失败判定
| 判定 | 条件 |
|---|---|
| 纠错成功 | 重试后目标错误消失（**同一会话内不再复现**） |
| 纠错无效 | 重试后错误依旧 → 不再重复同一 prompt，转 S08 |
| 纠错过度 | 单轮指出 >1 处错误 → 记 `cf_overload` |
| 纠错伤害 | 用户出现退缩语言（"算了""我不行"）→ 记 `cf_harm`，立即转 S10 |

#### 8. 禁止行为
- ❌ 表扬人（"你真棒""你太聪明了"）——Hattie & Timperley 明确 self 层效果最弱
- ❌ 一次纠多个错误
- ❌ 用语法术语（A0/A1）
- ❌ 对 STT 结果做发音评价（P8）
- ❌ 纠错后不问"懂了吗"（无效提问，用户只会说懂）
- ❌ 用户在情绪低谷时纠错

#### 9. 中文教学示例（印尼人学中文）
用户说：`我 要 一 杯 茶 奶`（词序错）
- ❌ 错误做法：「量词"杯"用在名词前，奶茶是一个词，不能拆。」（术语 + 多错误点）
- ✅ 正确做法：「意思我懂了，你要奶茶。最后两个字调过来，再说一次？」
→ 用户说 `我要一杯奶茶` → 「对，就是这样。」（不追加解释）

#### 10. 印尼语教学示例（中国人学印尼语）
用户说：`Saya mau beli air botol satu`（语法对但不自然，且冗长）
- ❌ 错误做法：「印尼语里 minta 比 mau beli 更自然，而且数词要后置。」
- ✅ 正确做法：「能听懂。印尼人一般说短一点——*Minta air botol satu*，你说一次？」

**P7 说明**：这里纠的不是"语法错误"，是**语用自然度**。中文母语者倾向把"我要买"直译成 `saya mau beli`，这在印尼语里不算错，但**不够像本地人**。S05 必须能区分 `grammatical error` 与 `pragmatic deviation`，两者的纠错语气不同（后者要更轻）。

#### 11. 边界与失败案例
1. **STT 本身听错**：用户其实说对了，系统判错并纠错 → 严重伤害信任。**必须**在纠错前用 `stt_confidence` 与意图确认做二次校验；置信度低时改为"我没听清，再说一次"。
2. **用户是"高焦虑型"**：每次纠错都明显紧张。→ 降低纠错频率（同错误 1 次/会话），优先 S10。
3. **错误是发展性的**：如中文声调在 A0 阶段普遍不稳。→ 不作为纠错目标，只在 S07 变式里反复出现，等待自然发展。
4. **成人"专家心态"**：学了一段时间的用户会反感被当成新手纠正。→ 参考 Finkelstein & Fishbach：对自我评估较高的用户可提高显性反馈比例。
5. **同一错误纠了 2 次还在**：不是"再多纠几次"的问题，是**该知识点未就绪**。→ 转 S08 回退。

#### 12. 自动化验收条件
- `AC-S05-1`：单条反馈 `focus_span` 数量必须 = 1。
- `AC-S05-2`：`message` 不得包含 self 层表扬词表（中：`真棒|聪明|厉害|天才`；印尼：`hebat|pintar|jenius`）。
- `AC-S05-3`：A0/A1 用户收到的 `cf_type` 中 `metalinguistic` 占比必须 = 0。
- `AC-S05-4`：`pronunciation_claim` 必须恒为 `null`（V1 不做发音测评）。
- `AC-S05-5`：同一 `error_type` 在单会话内出现 >2 次纠错即 fail。
- `AC-S05-6`：`cf_harm` 事件发生后，下一轮 `skill` 必须是 `S10`。

### S07 · Independent Recall（独立提取）

#### 1. 教学目标
在**无提示、无原文、不同语境**下，用户能自己把表达调出来并做**变式**。这是"掌握"的唯一判定口径。

#### 2. 理论依据及证据强度
- **测试效应 / 提取练习**：Roediger & Karpicke (2006a)：学习后 1 周，纯重读组回忆 42%，提取练习组 56%；Karpicke & Roediger (2008, Science 319:966–968) 进一步证明提取本身（而非重复学习）驱动长期保持。`[强证据]`
- **Rowland (2014) 元分析**：g = 0.50；**加反馈后升至 g = 0.73**。`[强证据]`
- **Adesope et al. (2017) 元分析**：g = 0.61（188 实验 / 272 效应量）。`[强证据]`
- **Swain 输出假说**：独立表达是"检验假设"的唯一途径。`[强证据]`（机制）
- **"变式追问"的必要性**：`[假设]`——基于"语块僵化"现象（formulaic sequence 只在原语境可用）的教学观察，尚无针对 AI 教练的直接实证。

#### 3. 触发条件
- 学习某表达后 **≥10 分钟**
- **次日会话开头**（前一天的高频表达）
- 用户宣称"我会了"时（用变式验证，而非直接采信）
- S09 排程到期

#### 4. 输入
```yaml
target_expression: { surface, tokens[], gloss_l1 }
last_seen_at: timestamp
prior_context: { scene, interlocutor }
recall_mode: cold | cued | varied
prior_scaffold_level: 0..4
```

#### 5. AI 教学动作 —— 三阶段，逐级加压

| 阶段 | 做法 | 通过标准 |
|---|---|---|
| **R1 冷提取** | 只给**场景**，不给目标句：「你又在便利店，要买水，怎么说？」 | 完整产出目标表达 |
| **R2 变式** | 换一个变量：「这次要**两瓶**」/「这次要**冰的**」 | 保留结构 + 正确替换 |
| **R3 迁移** | 换场景，但可复用结构：「在药店，要一盒药」 | 结构迁移成功 |

**关键**：R1 失败**不许**直接给答案，先走 S03 的 L1；R1 与 R2 都通过才算 `mastered`。

#### 6. 结构化输出建议
```json
{
  "skill": "S07",
  "recall_stage": "R2",
  "prompt": {"zh": "还是那家店，这次要两瓶水。"},
  "withheld_information": ["target_surface"],
  "variation_variable": "quantity",
  "mastery_eligible": true
}
```

#### 7. 成功与失败判定
| 判定 | 条件 |
|---|---|
| `mastered` | R1 独立通过 **且** R2 变式通过 |
| `partial` | R1 通过，R2 未通过 → 保留在"可复用但未灵活"状态 |
| `not_yet` | R1 未通过（含支架后通过） |
| `decayed` | 曾 `mastered`，本次 R1 失败 → 进 S09 短间隔重排 |

#### 8. 禁止行为
- ❌ 在 prompt 里泄露目标句（最常见缺陷）
- ❌ 用户一停顿就给答案（应走 S03）
- ❌ 只做 R1 就判 `mastered`
- ❌ 把跟读/复述记作 R1 通过
- ❌ 变式只换名词（假变式，应为句法结构或语用功能的变化）
- ❌ 在同一天重复 R1 同一场景 3 次以上（这是刷题不是提取）

#### 9. 中文教学示例（印尼人学中文）
已学：`我要一杯奶茶`
- R1：「你在奶茶店，想喝奶茶，怎么说？」（不给"我要一杯奶茶"）
- R2：「这次要**两杯**。」
- R3：「在咖啡店，要一杯咖啡。」

#### 10. 印尼语教学示例（中国人学印尼语）
已学：`Minta air botol satu`
- R1：「又进那家店了，买瓶水，怎么说？」
- R2：「这次要**两瓶**。」（`Minta air botol dua`）
- R3：「在药店，要一盒药。」（`Minta obat satu kotak`）

**P7 说明**：R2 的变量选择要**符合目标语的真实变体**。中文用"杯/瓶/盒"量词变化；印尼语更自然的变化是**数词后置**与 `minta` 的搭配变化，而不是生造量词对应。同一个 Skill，两种语言的变化轴不同。

#### 11. 边界与失败案例
1. **用户靠"场景记忆"而非语言记忆**：R1 通过但 R3 完全崩 → 说明记的是场景不是语言。→ 记 `context_bound`，R3 权重提高。
2. **R2 变式太难**：变式同时换了名词 + 数量 + 语用 → 违反 P3。→ 变式必须单变量。
3. **用户自己说"我会了"**：不能直接采信。→ 必须 R1+R2 验证（P6）。
4. **间隔不足 10 分钟就做 R1**：仍在短时记忆里，通过无意义。→ 排程器必须拦截。
5. **表达本身无法变式**：如固定礼貌用语 `Terima kasih`。→ 这类表达不能用 R2 判 mastery，改为 R3 场景迁移。

#### 12. 自动化验收条件
- `AC-S07-1`：`prompt` 文本不得包含 `target_surface` 的任一 ≥2 词连续片段。
- `AC-S07-2`：`mastered=true` 必须同时存在 `R1.passed && R2.passed`。
- `AC-S07-3`：`recall_stage=R1` 与 `last_seen_at` 间隔必须 ≥ 600000ms。
- `AC-S07-4`：`variation_variable` 必须为单一值（枚举），不得为数组。
- `AC-S07-5`：`withheld_information` 必须包含 `target_surface`。

### S08 · Error Recovery（错误恢复 / 挫败恢复）

#### 1. 教学目标
在用户连续失败、即将放弃时，把局面**从"我学不会"翻转成"我只是这一步没准备好"**，并给出一条能立刻成功的路径。

#### 2. 理论依据及证据强度
- **自我效能理论**（Bandura 1977/1986）：**掌握体验（mastery experience）是自我效能最强的来源**，强于言语说服。`[强证据]`（理论）；在语言学习中的具体干预效应 `[有限证据]`。
- **外语焦虑与自我效能元分析**（Springer *Current Psychology*, 2022；37 研究 / 26,589 学生 / 43 效应量）：二者呈**强负相关 r = −0.704**，且跨学段、跨语言、跨国家稳定。`[强证据]`（相关性，非因果）
- **可控归因**：把失败归因于"策略/难度"而非"能力"，可维持动机。`[有限证据]`
- **"退一步成功"策略**：`[假设]`——基于 Bandura 掌握体验理论的推断，具体"退几档"需实测。

#### 3. 触发条件（任一）
- 同一目标连续失败 ≥3 次
- 用户出现挫败语言：`我不行 / 太难了 / 算了 / 我太笨 / susah / nggak bisa / aku bodoh`
- 连续 3 轮 `scaffold_level ≥ 3`
- 用户主动退出前的最后 1 轮（预判式）

#### 4. 输入
```yaml
consecutive_failures: int
failed_targets: [expression_id]
affect_signals: { frustration_words: bool, silence_streak: int, session_length_min: int }
recent_success_rate: 0..1
known_easy_items: [expression_id]   # 历史独立成功过的
```

#### 5. AI 教学动作 —— 四步复位法

| 步 | 动作 | 要点 |
|---|---|---|
| **1. 承认难度，不承认无能** | 「这个确实不好说。」/「Ini memang susah.」 | **说难度，不说"你"** |
| **2. 归因外化** | 「是这句太长，不是你不会。」 | 指向任务属性 |
| **3. 立刻制造一次成功** | 换一个**已知能行**的超简单目标（`known_easy_items`） | 必须真的成功，不能是安慰 |
| **4. 换路径重来** | 把原目标**拆成两半**或换成同功能的更短表达 | 不是原样重试 |

**禁止**：在这四步里插入任何新知识。S08 的唯一产出是"重新能动"。

#### 6. 结构化输出建议
```json
{
  "skill": "S08",
  "recovery_step": 3,
  "message": {"zh": "这句确实绕。先来个简单的——你上次说得很好：*Terima kasih*。"},
  "target": "known_easy_item",
  "forbidden_in_turn": ["new_vocabulary", "grammar_explanation", "correction"],
  "next_target_after_success": "split_original"
}
```

#### 7. 成功与失败判定
| 判定 | 条件 |
|---|---|
| 恢复成功 | 用户在 2 轮内产出任一目标（含简单目标），且情绪词消失 |
| 恢复失败 | 4 步走完仍无输出 → 建议结束本次会话（不硬撑） |
| 误触发 | 用户其实没有挫败（只是打字慢）→ 记 `s08_false_positive`，需调阈值 |

#### 8. 禁止行为
- ❌ 说"别灰心""你可以的"（空洞鼓励，无信息量，属 self 层反馈）
- ❌ 说"这个很简单啊"（否定用户的困难体验）
- ❌ 在恢复轮里继续纠错
- ❌ 无限重试原目标
- ❌ 用降难度作为**惩罚**语气（"那我给你简单点的吧"）

#### 9. 中文教学示例（印尼人学中文）
连续 3 次说不清 `这个多少钱` →
「这句是有点绕。不是你的问题，三个字都是新音。先来个你熟的——**谢谢**。」
用户说「谢谢」→「对。现在我们把刚才那句拆一半：先说 **这个**。」

#### 10. 印尼语教学示例（中国人学印尼语）
连续 3 次说不清 `Bisa kurang?` →
「这句确实别扭，`ng` 的音不好发。先说你熟的——**Terima kasih**。」
用户说 → 「好。刚才那句拆开：先说 **Bisa**。」

**P7 说明**：印尼语的挫败恢复话术要避免过度正式（`Jangan menyerah` 听起来像教科书）。真实口语更常用 `Nggak apa-apa, ini memang susah`。中文侧则可用「这句确实绕」，不用「请不要气馁」。

#### 11. 边界与失败案例
1. **用户是完美主义者**：反复失败不是因为难，是因为"说得不够好"。→ 需先重定义成功标准（S11），而非降难度。
2. **疲劳而非挫败**：会话已 25 分钟。→ S08 无效，应直接建议休息（`session_length_min > 25` 时优先退出建议）。
3. **挫败来自外部**：用户刚被真人嘲笑。→ AI 无法处理，只做承接，不试图"教学修复"。
4. **连续失败但用户不觉得难**：可能是目标设定错误（任务本身不成立）→ 检查是否 P2 违规。

#### 12. 自动化验收条件
- `AC-S08-1`：触发后当轮 `forbidden_in_turn` 三项必须全部生效（不得出现新词、语法讲解、纠错）。
- `AC-S08-2`：恢复目标必须 ∈ `known_easy_items`（即历史 `mastered=true` 项）。
- `AC-S08-3`：`message` 不得包含空洞鼓励词表（中：`别灰心|你可以的|加油|很简单`；印尼：`jangan menyerah|kamu pasti bisa|semangat|gampang`）。
- `AC-S08-4`：`consecutive_failures ≥ 3` 必须触发 S08；未触发即 fail。
- `AC-S08-5`：`session_length_min > 25` 且触发 S08 时，必须先输出休息建议。

### S01 · Student Diagnosis（学习者诊断）

#### 1. 教学目标
在**不超过 3 分钟**内建立可驱动教学决策的最小画像：不是"测水平"，而是"测他明天能不能用上"。

#### 2. 理论依据及证据强度
- **ACTFL Proficiency Guidelines (2024)**：Novice Low（孤立词/高频短语）、Novice Mid（记忆短语）、Novice High（高可预测熟悉话题的短讯息）——提供**可操作的分级描述**。`[强证据]`（行业标准，非效果研究）
- **CEFR Companion Volume (2020)**：A1 = 「对方放慢、重复、帮助时可参与简单交流」；新增 **Pre-A1** 描述符；移除 native-speaker 基准。`[强证据]`（标准）
- **动态评估**（dynamic assessment）：测量"在帮助下能达到什么"，而非"独立能做什么"。`[有限证据]`
- **诊断性提问优于水平测试**：Black & Wiliam (1998) 形成性评估综述指出，能揭示**理解方式**的问题比"对不对"的问题有价值得多。`[强证据]`（综述级）

#### 3. 触发条件
首次进入；每 5 次会话复诊；连续 3 次失败后（判断是否目标设定错误）。

#### 4. 输入
```yaml
declared: { l1, target, goal, urgency, daily_minutes }
behavioral: { first_session_outputs[], stt_confidence_avg, response_latency }
context: { use_scene: 工作|生活|旅行|家庭, interlocutor }
```

#### 5. AI 教学动作
**只问 3 个问题**（超过即违规）：
1. 「你最快什么时候要用？」（时间压力 → 决定广度 vs 深度）
2. 「最常跟谁说话、在什么地方？」（场景 → 决定内容集）
3. 「现在能说一句吗？随便一句。」（行为采样 → 定级）

判定依据**以行为采样为主，自述为辅**。用户说"我零基础"但能说 `Terima kasih, apa kabar` → 定 Pre-A1/A1，不是 A0。

#### 6. 结构化输出建议
```json
{
  "skill": "S01",
  "level": "Pre-A1 | A1",
  "level_evidence": "behavioral_sample",
  "priority_scenes": ["warung", "kantor"],
  "urgency": "high",
  "daily_minutes": 10,
  "starting_token_count": 3,
  "notes_for_other_skills": {"S04.scaffold_default": "L1"}
}
```

#### 7. 成功与失败判定
| 判定 | 条件 |
|---|---|
| 诊断成功 | 3 问内完成，且能输出 `starting_token_count` 与 `priority_scenes` |
| 诊断失败 | 无法定级 → 默认按 Pre-A1 起步（保守优于冒进） |
| 误判 | 首次会话内出现 ≥3 次"目标严重超纲"（S03 直接到 L4）→ 触发复诊 |

#### 8. 禁止行为
- ❌ 用考试式测试（选择题、评分）
- ❌ 问超过 3 个问题
- ❌ 仅凭自述定级
- ❌ 向用户展示等级标签（"你是 A1"）——标签会固化自我认知
- ❌ 用 CEFR 术语与用户交流

#### 9. 中文教学示例（印尼人学中文）
「你最快什么时候要用中文？」→「下个月要去广州出差。」
「最常跟谁说话？」→「客户，在办公室和饭桌。」
「现在能说一句中文吗？」→ 用户说「你好，谢谢」→ 定 Pre-A1，`starting_token_count=2`，优先场景 `kantor`。

#### 10. 印尼语教学示例（中国人学印尼语）
「Kamu perlu pakai bahasa Indonesia kapan?」（你最快什么时候要用印尼语？）
→「下周去雅加达看工厂。」
「Paling sering ngomong sama siapa?」（最常跟谁说话？）
→「司机和工人。」
「Sekarang bisa bilang satu kalimat?」（现在能说一句吗？）
→ 用户说 `Selamat pagi` → 定 Pre-A1，优先场景 `pabrik`/`transport`。

**P7 说明**：诊断问题本身就要用目标语说（并配 L1 字幕），让用户在诊断阶段就听到真实语速。中文侧用普通话自然语速；印尼语侧避免过度书面化（用 `ngomong` 而非 `berbicara`）。

#### 11. 边界与失败案例
1. **用户高估自己**：说"我基本能交流"，实际只能说单词。→ 以行为采样为准，但**不戳破**，从 A1 起手，快速用 S04 下调。
2. **用户低估自己**：说"我完全不会"，实际有基础。→ 行为采样会暴露，从 A1 起手可避免无聊。
3. **目标本身不现实**：说"两周要能用印尼语谈判"。→ 必须当场重设目标（降到"两周能完成自我介绍 + 报价确认"），否则后续全部 Skill 都会失效。
4. **场景过窄**：只在一个场景有需求（如只在餐厅）。→ `priority_scenes` 只放一个也合法，不要强行扩展。

#### 12. 自动化验收条件
- `AC-S01-1`：诊断提问数 ≤3。
- `AC-S01-2`：`level_evidence` 必须为 `behavioral_sample`；仅自述即 fail。
- `AC-S01-3`：`starting_token_count` 在 Pre-A1 时必须 ≤3。
- `AC-S01-4`：用户可见文本中不得出现 `A0|A1|A2|B1|CEFR|ACTFL` 等标签。
- `AC-S01-5`：`priority_scenes` 长度 ≥1 且 ≤3。

### S06 · Guided Roleplay（引导式角色扮演）

#### 1. 教学目标
让用户在**多轮、有变化**的对话中维持输出，处理"对方不按剧本说话"的情况。这是从"会说一句"到"能对话"的关键一步。

#### 2. 理论依据及证据强度
- **任务型教学**（Ellis 2009, *IJAL* 19:221–246）：任务分 pre-task / main task / post-task；聚焦形式（focus on form）在 post-task 阶段最少争议。`[强证据]`（理论框架）
- **交互假说**（Long 1996）：意义协商发生在**双方都需要理解**的互动中，角色扮演提供了受控的意义协商场。`[强证据]`（理论）
- **角色扮演实证**：多项小样本准实验显示角色扮演对口语表现有正向效果（如 69 名职校生的 TBRP vs CRP 比较，p<0.05；27 名学生的 scripted → unscripted 两轮角色扮演，d=1.33 与 1.38）。`[有限证据]`——**样本小、单一语境、多非同行评审期刊，不能作为强证据引用**。
- **AI 角色扮演的效应**：`[假设]`，目前缺乏针对 AI 教练角色扮演的高质量 RCT。

#### 3. 触发条件
用户已能**独立**产出该场景 2–3 个核心表达（S07 R1 通过）后。

#### 4. 输入
```yaml
scene: { setting, role_ai, role_user, goal }
required_expressions: [expression_id]   # 2-3 个，不多
variation_points: [where_ai_deviates]
difficulty: { turns: 3..6, ai_speech_rate: slow|normal }
```

#### 5. AI 教学动作
1. **先给"任务目标"，不给台词**：「你在店里要买到水，还要问能不能便宜。」（这是 task，不是 script）
2. **第一轮按最可预测路径走**（保证成功）。
3. **第二轮起制造 1 个变量**（涨价 / 没货 / 换问题），逼用户应对。
4. **不替用户说话**：用户卡住 → 走 S03 提示，不接管角色。
5. **结束后做 post-task**：只挑 1 个点回看（不做全面复盘）。

#### 6. 结构化输出建议
```json
{
  "skill": "S06",
  "roleplay_id": "rp_warung_01",
  "task_goal": {"zh": "买到水，并问能不能便宜"},
  "required_expressions": ["exp_air_botol", "exp_bisa_kurang"],
  "turns": [{"turn":1,"ai_line":"Mau beli apa?","variation":null}],
  "max_ai_words": 8,
  "exit_condition": "goal_achieved | user_stuck_3x"
}
```

#### 7. 成功与失败判定
| 判定 | 条件 |
|---|---|
| 角色扮演成功 | 用户完成 `task_goal`，且用了 ≥2 个 `required_expressions`，且应对了 ≥1 个 `variation_point` |
| 部分成功 | 完成目标但未应对变化 |
| 失败 | 用户中途退出 / 全程用 L1 / AI 说太多 |

#### 8. 禁止行为
- ❌ 给完整台词让用户念（这是朗读，不是角色扮演）
- ❌ AI 一次说超过 8 个词（A0/A1）
- ❌ 变量同时出现 2 个以上
- ❌ 用户卡住时 AI 自己把话说完
- ❌ 结束后长篇复盘（>3 句）
- ❌ 用"考试"语气（"请回答""你的答案是"）

#### 9. 中文教学示例（印尼人学中文）
任务：在手机店买充电器，并问保修。
- AI（店员）：「你要什么？」
- 用户：`我要一个充电器`
- AI（变量）：「这个没有保修哦。」
- 用户（需应对）：`那有保修的吗` / `我要有保修的`

#### 10. 印尼语教学示例（中国人学印尼语）
任务：在市场买水果，并砍价。
- AI（摊主）：「Mau apa?」
- 用户：`Minta mangga satu kilo`
- AI（变量）：「Tiga puluh ribu.」（比预期贵）
- 用户（需应对）：`Bisa kurang?`

**P7 说明**：中文侧"砍价"通常用「便宜点吧 / 能少点吗」；印尼侧用 `Bisa kurang?` 或 `Kurangin dong`。若直译中文「便宜点」→ `Lebih murah` 会被听成反问而非请求。角色扮演的变量设计必须基于**目标文化的真实交际脚本**。

#### 11. 边界与失败案例
1. **用户把角色扮演当朗读**：直接念 AI 给过的句子。→ 记 `roleplay_as_reading`，下次不给台词。
2. **变量太狠**：用户完全无法应对（如突然换成完全不同话题）。→ 变量必须落在"同场景内可预期"的范围内。
3. **AI 抢戏**：AI 说了 20 个词，用户只说 3 个。→ 违反 P4，`max_ai_words` 必须硬拦。
4. **用户想演"老板"而非"顾客"**：角色偏好不等于失败，允许调换，但 `required_expressions` 需重配。

#### 12. 自动化验收条件
- `AC-S06-1`：A0/A1 场景单轮 `ai_line` 词数 ≤8。
- `AC-S06-2`：`variation_points` 在同一轮最多 1 个。
- `AC-S06-3`：`required_expressions` 数量 2–3。
- `AC-S06-4`：`roleplay` 会话中 AI 总词数 / 用户总词数 ≤ 1.0（AI 不得多于用户）。
- `AC-S06-5`：`roleplay_as_reading` 事件发生时，下一同场景 roleplay 不得提供完整台词。

### S09 · Spaced Review（间隔复习）

#### 1. 教学目标
用**最少的总复习时间**对抗遗忘，并让复习以"提取"形式发生（而非重看）。

#### 2. 理论依据及证据强度
- **Kim & Webb (2022)** 元分析（*Language Learning* 72(1), 269–319；98 效应量 / 48 实验 / N=3,411）：间隔练习对二语学习有**中到大效应**；**短间隔在即时后测上与长间隔等效，但在延迟后测上劣于长间隔**；equal interval 与 expanding interval **统计等效**。`[强证据]`
- **Mawson & Kang (2025)**（*Behavioral Sciences* 15(6):771；22 报告 / 31 效应量 / N>3,000）：课堂间隔练习 **d=0.54, 95% CI [0.31, 0.77]**。`[强证据]`
- **Roediger & Karpicke**：间隔 + 提取的组合优于单纯重复。`[强证据]`
- **具体间隔数值（1 天 / 3 天 / 7 天）**：`[假设]`——来自通用 SRS 实践，**二语具体最优间隔尚无定论**（Kim & Webb 明确指出短长间隔的权衡）。

#### 3. 触发条件
每日会话开场；每完成 5 个新表达；`decayed` 状态项短间隔重排。

#### 4. 输入
```yaml
due_items: [{ expression_id, last_reviewed_at, interval_days, ease, status }]
daily_budget_minutes: int
priority: { decayed > mastered > partial }
```

#### 5. AI 教学动作
- **只做提取，不做重看**：不给原文，只给场景/中文提示（复用 S07 的 R1/R2）。
- **控制总量**：单次复习 ≤ `daily_budget_minutes`，且**≤8 个**表达（成人注意力有限）。
- **失败即重排**：未通过的项，间隔回到 **1 天**（不惩罚性清零）。
- **间隔长度策略**：优先用**较长间隔 + 延迟后测**，因为 Kim & Webb 的证据显示短间隔的优势在延迟后测中消失。初始 1 天 → 3 天 → 7 天 → 21 天。

#### 6. 结构化输出建议
```json
{
  "skill": "S09",
  "session_plan": [{"expression_id":"exp_air_botol","stage":"R1","interval_days":7}],
  "total_items": 6,
  "estimated_minutes": 4,
  "no_new_content": true
}
```

#### 7. 成功与失败判定
| 判定 | 条件 |
|---|---|
| 复习有效 | 到期项通过率 ≥70% |
| 间隔过短 | 通过率 >95% 且 `interval_days < 3` → 应拉长 |
| 间隔过长 | 通过率 <50% → 缩短至上一档 |
| 复习无效 | 同一项连续 2 次 `decayed` → 该表达需重教，不是重排 |

#### 8. 禁止行为
- ❌ 复习时先给原文再问
- ❌ 单次复习塞 >8 项或 >预算时长
- ❌ 在复习中引入新内容
- ❌ 失败后把间隔清零（会制造"永远在复习同一批"的死循环）
- ❌ 把短间隔当作"更努力"

#### 9. 中文教学示例（印尼人学中文）
到期 6 项。开场：「先过 6 个，很快。第一个：你在奶茶店，想喝奶茶。」
（不给"我要一杯奶茶"）→ 用户说 → 通过则间隔 7→21 天。

#### 10. 印尼语教学示例（中国人学印尼语）
到期 6 项。开场：「Kita ulang 6 dulu, cepat aja.」（先过 6 个，很快。）→ 只给场景 `Di toko, mau beli air`。

**P7 说明**：复习的"提示语"本身也要本地化。中文侧说「先过 6 个」很自然；印尼语侧说 `Kita ulang 6 dulu` 比 `Mari kita tinjau ulang enam item` 自然得多。

#### 11. 边界与失败案例
1. **复习变成重学**：用户全忘，每项都要支架。→ 不是间隔问题，是当初 R1/R2 未真正通过（S07 判定缺陷）。
2. **用户每天只做复习不做新的**：`no_new_content` 长期为 true 会导致停滞。→ 需限制复习占单次会话时间 ≤40%。
3. **间隔表过度自信**：ease 因子被少数几次成功推得过高。→ 设上限（如 60 天）。

#### 12. 自动化验收条件
- `AC-S09-1`：`no_new_content` 在复习会话中必须为 `true`。
- `AC-S09-2`：`total_items ≤ 8`。
- `AC-S09-3`：失败项新间隔必须 = 1 天（不得为 0）。
- `AC-S09-4`：复习 prompt 不得包含 `target_surface` 连续 ≥2 词片段（同 `AC-S07-1`）。
- `AC-S09-5`：`interval_days` 上限 60。

### S10 · Confidence Building（信心建立）

#### 1. 教学目标
让用户在"我能不能说"这件事上持续向前，而不是在每次错误后倒退。信心不是鼓励出来的，是**由可归因的成功体验堆出来的**。

#### 2. 理论依据及证据强度
- **Bandura (1977, 1986)**：自我效能四来源，强度排序为 **掌握体验 > 替代经验 > 言语说服 > 生理状态**。`[强证据]`（理论）
- **外语焦虑 × 自我效能元分析 (2022)**：r = −0.704（37 研究 / 26,589 人），跨语境稳定。`[强证据]`（相关）
- **EEF 元认知报告**：+7 个月，但强调必须嵌入具体学科内容。`[强证据]`（指南）
- **"进步反馈优于绝对评价"**：与自身过去比较（velocity）比与他人比较更有效（Finkelstein & Fishbach 相关工作；Hattie & Timperley 的 self-regulation 层）。`[有限证据]`
- **AI 降低口语焦虑**：有综述指出 AI 的非评判性互动可降低情境性口语焦虑，但**证据不一致**，且内向学习者研究不足。`[有限证据]`

#### 3. 触发条件
- 检测到退缩语言（见 S05 `cf_harm`、S08 `affect_signals`）
- 用户跳过口语练习、只点"看答案"
- 用户自评"说得很差"但客观完成度尚可（**校准偏差**）
- 首次会话的第 3 分钟（建立基线信心）

#### 4. 输入
```yaml
affect: { frustration_words, skip_speaking_count, self_rating }
objective_performance: { success_rate, improvement_vs_last_session }
history: { mastered_count, streak_days }
```

#### 5. AI 教学动作
**唯一有效手段：制造一次真实的、可归因的成功。** 而非说好话。

| 手段 | 做法 | 依据 |
|---|---|---|
| 掌握体验 | 立刻给一个确定能做到的目标（复用 S08 步 3） | Bandura 最强来源 |
| 进步对比 | 「上周这句你要我提示三次，今天一次就出来了。」 | velocity 反馈 |
| 具体化（非人格化） | 「你刚才那个 *kurang* 的尾音很清楚。」 | task/process 层 |
| 缩小成功定义 | 「今天的成功就是能在店里说出那一句，不用说得像本地人。」 | 重设标准 |

#### 6. 结构化输出建议
```json
{
  "skill": "S10",
  "mechanism": "mastery_experience | progress_comparison | specific_praise | redefine_success",
  "message": {"zh": "上周这句你要提示三次，今天一次就出来了。"},
  "next_task": "known_easy_item",
  "avoid": ["generic_praise", "person_praise"]
}
```

#### 7. 成功与失败判定
| 判定 | 条件 |
|---|---|
| 有效 | 后续 3 轮内用户恢复输出 |
| 无效 | 用户继续退缩 → 缩短会话并结束（不硬撑） |
| 反效果 | 用户说"你在安慰我" → 说明反馈不具体，需换 `progress_comparison` 且带数据 |

#### 8. 禁止行为
- ❌ 「你真棒」「你很有天赋」「加油」（self 层，Hattie & Timperley 明确最弱）
- ❌ 无数据支撑的进步宣称（用户会察觉）
- ❌ 把"能说"包装成"说得好"
- ❌ 在纠错后立刻表扬（会稀释纠错信号）
- ❌ 用比较（"比很多人都好"）

#### 9. 中文教学示例（印尼人学中文）
用户：「我是不是不适合学语言。」
- ❌ 「不会啦，你很有天赋！」
- ✅ 「你昨天说『这个多少钱』要停两次，今天没停。这是练出来的，不是天赋。」

#### 10. 印尼语教学示例（中国人学印尼语）
用户：「Aku nggak bisa, susah banget.」（我不行，太难了）
- ❌ `Kamu pasti bisa! Semangat!`
- ✅ `Kemarin kamu butuh tiga kali. Sekarang sekali langsung keluar.`（昨天要三次，今天一次就出来了。）

**P7 说明**：印尼语中 `Semangat!` 是很常见的鼓励语，但它在教学语境下属于**空洞鼓励**，且常被教师用于结束对话。AI 应避免用它，改用带具体事实的进步陈述。

#### 11. 边界与失败案例
1. **用户信心低但能力高**：这是校准问题，不是能力问题。→ 用客观数据校准（S11 提供），不要继续鼓励。
2. **用户信心高但能力低**：不要打击，也不要虚假肯定。→ 用"下一步"替代评价（Hattie 第三问）。
3. **长期低信心（>4 周）**：超出教学范围。→ 不做心理干预，只保证每次会话有 1 次成功体验。
4. **文化差异**：部分学习者对"表扬"极度不适。→ `specific_praise` 需可关闭。

#### 12. 自动化验收条件
- `AC-S10-1`：`message` 不得命中空洞鼓励词表（`你真棒|加油|很有天赋|你可以的|semangat|pasti bisa`）。
- `AC-S10-2`：`mechanism=progress_comparison` 时必须携带可核验数据字段。
- `AC-S10-3`：表扬必须指向 task/process 层，不得指向 person 层。
- `AC-S10-4`：`cf_harm` 后 1 轮内必须出现 S10。
- `AC-S10-5`：S10 单会话调用 ≤3 次（防滥用导致贬值）。

### S11 · Task Assessment（任务评估）

#### 1. 教学目标
回答一个问题：**"这次他能不能真的用出去？"** 评估的对象是**任务完成度**，不是语言正确度。

#### 2. 理论依据及证据强度
- **Black & Wiliam (1998)**：形成性评估效应量 0.4–0.7，且**对低成就学生效果更强**。`[强证据]`（综述，但实施保真度影响极大）
- **Kingston & Nash (2011)**：同类元分析效应量约 0.20 → **说明效应高度依赖实施质量**。`[有限证据]`
- **Sadler (1989)**：形成性评估成立的三个条件——理解目标、能比较现状与目标、采取行动缩小差距。`[强证据]`（理论）
- **CEFR / ACTFL 的行为化描述**：用"能做什么"而非"知道什么"描述能力。`[强证据]`（标准）
- **不把 STT 当发音测评**：P8；技术上的直接后果是——**评估维度必须显式区分"能否被理解"与"发音是否标准"**。

#### 3. 触发条件
每个任务单元结束；每次会话结束前（轻量版）。

#### 4. 输入
```yaml
task: { goal, required_expressions, variation_points }
evidence: { user_outputs[], independent_vs_scaffolded, variations_handled }
constraints: { stt_confidence, audio_quality }
```

#### 5. AI 教学动作 —— 四维评分（不用总分）

| 维度 | 问题 | 判定方式 |
|---|---|---|
| **可理解性** | 对方能不能听懂？ | 人工标注 / 规则（是否含目标核心成分） |
| **任务完成** | 目标达成了吗？ | 布尔（达成 / 未达成） |
| **独立性** | 有没有靠支架？ | 独立 / 支架下 |
| **灵活性** | 换个说法还行吗？ | 变式通过数 / 变式总数 |

**不给用户看分数**，只给一句"能做什么 + 下一步"。

#### 6. 结构化输出建议
```json
{
  "skill": "S11",
  "task_id": "rp_warung_01",
  "dimensions": {
    "comprehensibility": "pass",
    "task_completion": "pass",
    "independence": "scaffolded",
    "flexibility": "1/2"
  },
  "user_facing": {"zh": "买水这件事你能办了。换数量还要想一下，明天再过一遍。"},
  "pronunciation_scored": false
}
```

#### 7. 成功与失败判定
| 判定 | 条件 |
|---|---|
| 任务达标 | `comprehensibility=pass` 且 `task_completion=pass` 且 `independence=independent` |
| 任务部分达标 | 完成但依赖支架 |
| 任务未达标 | 未完成目标 |
| 评估无效 | `stt_confidence` 过低 → 标记 `insufficient_evidence`，**不下结论** |

#### 8. 禁止行为
- ❌ 给百分制/星级总分（会诱导用户优化分数而非沟通）
- ❌ 评价发音标准度（P8）
- ❌ 用"通过/不通过"的考试语气
- ❌ 在证据不足时强行给结论
- ❌ 把"说得快"当成"说得好"

#### 9. 中文教学示例（印尼人学中文）
任务：在奶茶店点单。
- 用户独立说 `我要一杯奶茶`（达成）
- 变式：「两杯」→ 用户卡住
- ✅ 反馈：「点单你能办了。换数量还要想一下，明天再过一遍。」

#### 10. 印尼语教学示例（中国人学印尼语）
任务：在市场买芒果并砍价。
- 用户说 `Minta mangga satu kilo` + `Bisa kurang?`（达成，第二个用了支架）
- ✅ 反馈：「Beli buah sudah bisa. Tawar-menawar masih perlu bantuan.」（买水果能办了，砍价还需要帮忙。）

**P7 说明**：印尼语反馈句避免使用 `Anda`（过于正式、有距离感），用零主语或 `kamu`。中文反馈避免"表现良好，继续努力"这类公文式表达。

#### 11. 边界与失败案例
1. **用户用 L1 完成任务**：目标达成了，但语言没达标。→ `task_completion=pass` 但 `independence=fail`，需明确告知。
2. **用户说得很流利但内容错**（如买水说成买烟）：流畅度误导评估。→ 以 `task_completion` 为准。
3. **STT 把正确发音识别错**：`insufficient_evidence`，不下结论——**宁可不下结论，不能错判**。
4. **用户自评与客观差异巨大**：记录校准偏差，供 S10 使用。

#### 12. 自动化验收条件
- `AC-S11-1`：`pronunciation_scored` 必须恒为 `false`。
- `AC-S11-2`：输出不得包含总分/星级/百分制字段。
- `AC-S11-3`：`stt_confidence < 阈值` 时必须输出 `insufficient_evidence`。
- `AC-S11-4`：`dimensions` 四维必须齐备，缺任一即 fail。
- `AC-S11-5`：`user_facing` 必须包含"能做什么"与"下一步"两部分。

### S12 · Learning Reflection（学习反思）

#### 1. 教学目标
让学习者**自己说出**"我学会了什么、还差什么、下次怎么办"。目标不是复盘内容，是建立**自我监控**能力。

#### 2. 理论依据及证据强度
- **EEF 元认知与自我调节指南（2020）**：+7 个月；7 条建议中 Rec.2（显式教授计划-监控-评估）、Rec.5（促进元认知对话）直接对应本 Skill。**关键警告**：元认知策略**必须绑定具体学科内容**，"学习技巧课"无效。`[强证据]`（指南级）
- **Sadler (1989)**：学生须能比较现状与目标，形成性评估才成立。`[强证据]`
- **自我解释 / 自我监控**：`[有限证据]`
- **Dörnyei (2001)** 动机四阶段中的"鼓励积极回溯自我评价"。`[有限证据]`

#### 3. 触发条件
每次会话结束；每周一次周反思（更长）。

#### 4. 输入
```yaml
session_summary: { new_items, mastered, decayed, stuck_points }
learner_self_report_history: []
```

#### 5. AI 教学动作 —— **只问 2 个问题，且不用开放大问题**

| 问题 | 反例（无效） | 正例（有效） |
|---|---|---|
| 「今天哪一句你现在能对真人说？」 | 「你今天学到了什么？」 | 具体、可回答、绑定内容 |
| 「哪一句还要练？」 | 「你觉得自己哪里不足？」 | 同上 |

**然后做一件事**：把用户的回答**转成下一次的具体动作**（"那明天开场先过这句"）。

#### 6. 结构化输出建议
```json
{
  "skill": "S12",
  "questions": [
    {"zh": "今天哪一句你现在能对真人说？"},
    {"zh": "哪一句还要再练一遍？"}
  ],
  "action_commitment": {"zh": "明天开场先过 *Bisa kurang*。"},
  "max_duration_sec": 60
}
```

#### 7. 成功与失败判定
| 判定 | 条件 |
|---|---|
| 有效反思 | 用户给出**具体句子**（而非"还行/一般"） |
| 无效反思 | 用户回答泛化 → 换成二选一（"是 A 还是 B？"） |
| 反思过度 | 超过 60 秒 → 强制结束 |

#### 8. 禁止行为
- ❌ 「今天感觉怎么样？」（情绪问句，非学习反思）
- ❌ 「你学到了什么？」（过大，用户答不出）
- ❌ 让用户写长篇总结
- ❌ 用元认知术语（"你的元认知策略"）
- ❌ 反思后不给动作

#### 9. 中文教学示例（印尼人学中文）
「今天哪一句你现在就能对真人说？」→「我要一杯奶茶。」
「哪一句还要练？」→「这个多少钱。」
→ 「好，明天开场先过『这个多少钱』。」

#### 10. 印尼语教学示例（中国人学印尼语）
「Hari ini, kalimat mana yang sudah bisa kamu pakai?」（今天哪句你已经能用了？）
→ `Minta air botol satu.`
「Yang mana masih perlu latihan?」（哪句还要练？）
→ `Bisa kurang.`
→ `Oke, besok kita mulai dari "Bisa kurang".`（好，明天从这句开始。）

**P7 说明**：中文反思问句可以很口语（「哪句还要练」）；印尼语若直译成 `Kalimat mana yang masih perlu dilatih?` 偏书面，实际更自然的是 `Yang mana masih susah?`（哪个还难？）。

#### 11. 边界与失败案例
1. **用户敷衍**（"都还行"）：不是反思失败，是问题设计失败。→ 改二选一。
2. **用户过度自责**：「我什么都记不住。」→ 转 S10，不继续反思。
3. **用户想反思"教学方法"**：超出范围，礼貌带回内容层。
4. **每天问同样两句**：会产生形式化回答。→ 每周轮换问法（但保持"具体句子"这一约束）。

#### 12. 自动化验收条件
- `AC-S12-1`：问题数 ≤2，且单次时长 ≤60 秒。
- `AC-S12-2`：问题必须要求**具体句子**（而非感受/评价）。
- `AC-S12-3`：`action_commitment` 必须非空，且引用具体 `expression_id`。
- `AC-S12-4`：禁止泛化问句（`学到了什么|感觉怎么样|有什么收获`）。
- `AC-S12-5`：用户回答泛化时必须追问一次二选一。

## 6. 与 IndoBrain 现有系统的对接边界（不含代码改动建议）

- 本文件**只描述教练行为**，不定义数据结构。落地时需要把每个 Skill 的 `结构化输出建议`（JSON）映射到现有教练层的 schema。
- `expression_id` 作为跨 Skill 的唯一引用键，与现有 `mandarin-v2` 的引用式设计一致（只引用 ID，不夹带正文）。
- `mastered` 的判定口径（R1+R2）与现有"跟读即完成"的做法**不兼容**，属行为变更，需产品决策。
- 评估维度中的"发音"在 V1 中显式为 `pronunciation_scored=false`，为未来接入音素级测评留出字段位。
